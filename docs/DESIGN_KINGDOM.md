# DESIGN_KINGDOM.md — 王国领地系统设计（城建经营 × 养成新维度）

> 2026-07-19 立项设计稿，同日用户拍板通过（四原则：塔维度/推荐资源方案/卖时间不卖上限·节奏运营策划控/服务器权威永久）。K0~K5 已实施（见 HISTORY 2026-07-19 条；K2 同日按用户反馈改 SLG 场景化主城），K6 IAP 待排。背景：主界面 CR 改版已留「王国」页签口子（KAN-111）；
> 目标 = 拓展养成维度、成为 F2P 商业化（IAP）的长线收入来源。
> 定位对标：CR 的 King Level + COC/口袋奇兵式轻城建，压缩进「单页签自闭环」的体量。
> 所有数值均〔示意·待平衡〕；服务器权威（决策 48）与 lockstep 确定性（V4 红线）为硬约束。

## 1. 一句话定位

**你是汉末一方诸侯**：经营自己的城池（建造/升级/收取），城建产出反哺卡牌养成（金币），
**城防建设直接强化战场上你的三座塔**——这是王国系统输出到对战的**唯一数值维度**。

## 2. 为什么选「塔」作为对战数值维度（推荐案）

| 候选维度 | 评估 |
|---|---|
| **塔属性（推荐）** | ✅ 唯一没被现有养成占用的板块（卡有 level/rank，塔是白板）；主题严丝合缝（修城→城塔更硬）；CR 已验证（King Level）；PVE 攻防两用、PVP 可对称下发 |
| 全军百分比 buff | ❌ 与卡牌 level 乘区高度重叠，玩家感知模糊，数值排查困难 |
| 圣水/抽卡节奏 | ❌ 动战斗节奏 = 动 lockstep 确定性与平衡根基，风险最大 |
| 新资源型消耗品（战前 buff） | ❌ 每局前置操作，违背「即点即玩」，且消耗品经济容易通胀 |

注意与既有拍板的关系：KAN-76 的「塔不随**卡牌**养成缩放」不变——塔属性归**王国**这条新线管，
两条养成线各管一块，互不越界。

## 3. 核心循环

```
建造/升级建筑（花 粮草+木石 + 等待时间）
   → 产出资源（粮草/木石/金币）+ 城防提升
      → 金币反哺卡牌养成（升级/升阶）
      → 城防强化三塔 → 打 PVE/PVP 更顺
         → 通关解锁新地块与王城上限 → 回到建造
```

时间（timer）是核心节拍器：等待 → 想加速 → 宝石/IAP。这是本系统的商业化底座。

## 4. 资源体系（自成一套，与主经济区隔）

| 资源 | 来源 | 用途 | 与主经济关系 |
|---|---|---|---|
| **粮草** | 农田（按小时产出，有仓储上限） | 民生类建筑升级 | 王国内闭环，不可交易 |
| **木石** | 工坊（伐木+采石合一，简化） | 城防类建筑升级 | 王国内闭环，不可交易 |
| **金币** | 铸币坊（整合现有挂机金库） | 卡牌养成（既有用途） | 王国 → 主经济 单向输出 |
| **宝石** | 既有硬通货 | 加速计时/补资源缺口 | 主经济 → 王国 单向输入（IAP 兑换点） |

**关键闸门：金币不能买粮草/木石。** 城防（=对战数值）只能靠时间或宝石推进——付费路径清晰，
也避免金币通胀直通对战数值。

## 5. 建筑清单（P0 首版 7 个）

| 建筑 | 功能 | 数值挂点〔示意〕 |
|---|---|---|
| **王城** | 等级门：其余建筑等级 ≤ 王城等级；王城升级额外要求章节进度（第N章通关解锁 LvN 段） | Lv1~10，绑 国王征途 10 章 |
| **农田** | 产粮草/小时，登录收取（挂机式） | 产率随等级；仓储上限约束 |
| **工坊** | 产木石/小时 | 同上 |
| **粮仓** | 提高粮草/木石存储上限 | 节奏调控工具（防囤爆） |
| **城墙** | ★对战维度：**三塔 HP 加成** | +3%/级〔示意〕，Lv 上限=王城 Lv×2 |
| **箭楼** | ★对战维度：**三塔攻击加成** | +2%/级〔示意〕，同上 |
| **铸币坊** | 产金币/小时——**接管现有挂机金库**（rate = 现 `gold_per_hour_per_chapter` 曲线 × 铸币坊系数），主界面挂机入口保留、数值来源切到这里 | 平滑迁移，无体验断层 |
| 工匠营（P1） | 工匠队数量：同时施工数。默认 1 队，第 2 队 = 大额宝石/IAP | 经典 COC 付费点 |

## 6. 对战数值接口（工程口径）

- **城防汇总**：`tower_hp_mult = 1 + 0.03×城墙Lv`、`tower_dmg_mult = 1 + 0.02×箭楼Lv`〔示意〕。
  顶配约 塔 HP +60% / 塔攻 +40%〔示意，S8/KAN-87 平衡复盘时定终值〕；**天花板绑王城=绑章节**，
  数值上限可控、不失控 P2W。
- **服务器唯一权威**：等级/资源/计时全在 PG；mult 由**服务端算好定值下发**（整数分位存储，
  避免浮点 pow；两端不各自计算）——沿用 KAN-76「level/rank 权威下发 + 双端对称注入」的成熟管线。
- **PVE**：`pve_start` 响应带我方 tower mult，battle 注入我方三塔；敌塔照旧走关卡 coef。
  重放验证器同样吃下发值，反作弊闭环不变。
- **PVP**：`JoinRoomResp` 扩展 `side1/side2_tower_mult`（学 CardProgress 字段 9/10 的加法），
  双端对称注入 + state hash 对帐；匹配沿用 2026-07-02 拍板口径（完全生效、MMR 收敛、
  建房日志埋 `def[hp/dmg]` 观察口）。
- **确定性红线**：mult 进 lockstep 的路径全用「服务器定值 + 乘法」，禁 pow/本地推导。

## 7. 商业化设计（IAP 挂点，随全局 IAP 线后置实装）

| 付费点 | 类型 | 说明 |
|---|---|---|
| 加速（计时跳过） | 消耗型 | 城建 timer 的标准变现；按剩余时长定价 |
| 资源礼包（粮草/木石） | 消耗型 | 缺口补齐；与加速互补 |
| 第二工匠队 | 永久解锁 | 高价锚点单品（COC 验证） |
| 王国月卡 | 订阅型 | 产出 +50% + 每日宝石；长线留存收入主力 |
| 城池/塔皮肤 | 装饰型 | **塔皮肤在对战中可见**（双方都看得到）= 无数值炫耀型消费；与三国阵营皮肤天然契合（A3 已有塔分阵营皮肤储备） |

立场：**卖时间不卖天花板**——付费加速进度，但数值上限（王城=章节门）全服同一条线。
装饰与订阅承接长期收入，减少纯数值付费的公平性反噬。

## 8. 与宫廷/外交页签的边界（留口子不实做）

- **宫廷**（未来）：武将/官员系统——官员可「驻守」王国建筑加产出（王国界面预留灰态驻守位）；
  武将与卡牌联动另行设计。
- **外交**（未来）：联盟/社交——资源互赠、联盟援建加速（王国界面预留灰态「援建」按钮）。
- 王国 P0 完全自闭环，不依赖上述两者。

## 11. K7 · 9 栋 placeholder 建筑功能设计（2026-07-27 立稿·用户拍板三分叉；2026-08-30 决策 49 改写为卡通术语，机制不变）

> 背景：2026-07-26 王国正式城建场景接入（KAN-112）把建筑从 7 扩到 16，其中 **9 栋是 placeholder**
> （四兵营〔魔法书院/枪/弩/骑〕 + 采石场/科研所/炼铁厂/牧场/晶石商店）——可建造、建成点击 = 「敬请期待」toast。本节给这 9 栋定真实功能。
> **用户拍板（2026-07-27）**：①兵营 = 碎片产线；②城建资源 2 种 → 4 种；③商店 = 互市 + 碎片位都做。

### 11.1 不可破的既有约束（设计边界）

1. **塔是王国输出到对战的唯一数值维度**（§2）→ 9 栋新建筑**一律不得**给单位/全军任何战斗百分比。
2. **金币铁门**（§4）：gold 不能购买任何城建资源；`config.validate()` 已在服务端把这条焊死，新资源同样进白名单校验。
3. **卖时间不卖天花板**（§7）：新建筑只加"产出/储量/碎片速率"，等级天花板仍绑城堡 = 绑章节。
4. **不过度设计**：能纯配表就不写代码——服务端 `producer` kind 已完全配表驱动。

### 11.2 九栋功能总表

| 建筑 | kind | 功能 | 工程量 |
|---|---|---|---|
| **采石场** quarry | producer | 产 **石料 stone**（新资源） | 纯配置·零代码 |
| **牧场** ranch | producer | 产 **粮草 food**（副粮源，产率低于农田，自带独立囤积上限） | 纯配置·零代码 |
| **炼铁厂** ironworks | producer | 产 **铁锭 iron**（新资源，慢产 = 后期稀缺料） | 纯配置·零代码 |
| **科研所** stoneworks | storage | 石料/铁锭 专用仓（提高 stone/iron 存储上限） | 小改：仓储通用化 |
| **魔法书院/枪/弩/骑 兵营** ×4 | barracks（新） | 指定一张该兵种类别的「训练目标卡」，按小时慢速产出**该卡碎片**，登录领取 | 中：新 kind + 结算 + 目标卡 UI |
| **晶石商店** shop | market（新） | ①资源交换：每日限次资源对换；②碎片位：每日刷新商品，金币买碎片 | 中：新 API + 新表 + 新页 |

### 11.3 资源体系：2 种 → 4 种

| 资源 | 产源 | 主要去向 | 备注 |
|---|---|---|---|
| **食物 food** | 农田 + **牧场** | 民生建筑、兵营运转 | 已有（原「粮草」，决策 49 改称） |
| **木材 wood** | 魔法工坊（workshop；0830 卡通场景为紫蘑菇魔法工坊） | 通用建材 | 已有；原"木石合一"语义拆分为纯木材 |
| **石料 stone**（新） | **采石场** | ★**城防建筑（城门/箭塔）主料** | 强化"城防只能靠时间或宝石"的付费路径 |
| **铁锭 iron**（新） | **炼铁厂** | 兵营各级 + 城堡高段 | 产率最慢，做后期节流阀 |

**建筑间依赖成型**：不建采石场 → 城防中后期直接卡死；不建炼铁厂 → 兵营与城堡高段卡死。
这是城建"先建什么"的决策深度来源，也让 9 栋 placeholder 不再是可有可无的装饰。

**老号兼容（硬要求，零迁移）**：
- 新资源初始持有 0；`rules.initial.resources` 只给新号发放少量。
- **城门/箭塔 Lv1~5 配方不动**，Lv6 起才要求 stone；城堡 Lv6 起才要 stone/iron。
  → 现有存档不会因为"没建采石场"而卡在半路，新料只在中后期出现，前期体验完全不变。
- `resources[]` 增补 + `base_storage` 补 stone/iron 条目即可，服务端 `pendingProduction`/`applyStorageCap` 全按 map 走，**无需改代码**；
  proto 侧 `resources` 是 `repeated ResourceAmount`，**无需改 proto**。

### 11.4 兵营 = 碎片产线（拍板案）

**卡牌新增分类字段** `troop_class`（`config/cards.json`，48 张全覆盖，纯配置）：

| class | 对应兵营 | 含义 | 归类规则 |
|---|---|---|---|
| `mage` | 魔法书院 | 法系/精灵系施法者 | 施法/精灵/元素类（原 `infantry` 步类随建筑顶替改义，决策 49） |
| `spear` | 枪兵营 | 近战重甲/坦克/群战 | 近战 + 高 HP 或多体 |
| `crossbow` | 弩兵营 | 远程物理 | attack_range 远 + 地面 |
| `cavalry` | 骑兵营 | 高速突击 / 空军 | move_speed 高 或 target_type=air |
| `none` | — | 法术 / 建筑 / 非四类 | **不进兵营**，碎片仍走开箱与商店 |

分类先按 `units.json` 属性给出候选（射程/速度/血量/target_type），**最终一张张人工定表**（决策 49 后按 31 可玩卡先定、17 锁卡素材到位再补），随 K7c 交付。

**产出规则**：
- 每座兵营内玩家**指定一张该类别的训练目标卡**（可随时更换；换目标**清空该营未领取的碎片**，防"攒一大坨再挑最需要的卡"套利）。
- 产率 `shard_rate_per_h` 随兵营等级线性增长，累积上限 `shard_storage` = 产率 × 6h〔示意〕。
- 领取与资源收取**同一个「收取」动作**（一次点击结清全部），碎片直接进 `economy_cards.shards`。
- 定位 = **慢速保底管线**：碎片主来源仍是开箱/关卡奖励；兵营让"我就想练这张卡"有一条确定但缓慢的路。
  首版建议 Lv1 = 2 碎片/时〔示意〕，四营全开也远低于正常开箱产量。

**为什么不给战斗 buff**：违反 §2 铁律（塔是唯一维度），且与卡牌 level/rank 乘区重叠、平衡不可排查。

### 11.5 晶石商店 = 资源交换 + 碎片位（拍板案：两者都做）

**A · 资源交换（原「互市」）**
- 任意两种城建资源之间对换，**有损耗**（如 `2 : 1`〔示意〕，比价随资源稀缺度分档：木/粮便宜，石/铁贵）。
- **每日限额**随商店等级提升；日切按服务器时钟（UTC+8 固定日界，与其他日常同口径）。
- ❌ 不做「资源 ↔ 金币」任一方向：换出会金币通胀，换入直接破 §4 铁门。

**B · 碎片位（金币买碎片）**
- 每日刷新 **N 个商品位**（N 随晶石商店等级，首版 3~5），每位 = 某张已解锁卡的固定份量碎片 + 金币标价。
- **刷新确定性**：种子 = `hash(account_id, 日期)`，**服务器算**——客户端无法预知也无法重刷；不提供付费刷新（首版）。
- **每位限购 1 次**，售罄不补 → 金币→碎片的日产量有硬天花板，堵住"氪金币直冲战斗力"。
- 与兵营的关系：兵营 = 定向慢产（自选目标），晶石商店 = 随机快产（看运气），互补不重叠。

**风险与对策**：金币→碎片→升阶 = 金币间接通向战斗力。对策 = 日限购硬顶 + 只售**已解锁**卡的碎片（不加速新卡解锁）+ 定价随卡稀有度分档。
