# ADR 0004：全 3D 表现，保留平面确定性战斗

- 日期：2026-10-24
- 决策：用户已确认迁移方向；实现分步推进，尚未全量落地。

## 背景

小小的静态模型、骨骼动画和 Godot 展示台验证了基本资产链路。用户要求整个项目转为真正 3D，并明确保留现有平面战斗规则、2D 菜单和 HUD。

## 决策

1. 3D 是表现层替换：战场、单位、塔、王国改用 Godot 3D 场景；UI 仍使用 Control / CanvasLayer。
2. `logic/` 保留抽象 tile Vector2、10Hz tick、流场寻路、自写软分离和 hash；不以 3D 物理或渲染帧推进结算。
3. 1 tile 默认映射 1 个 3D 世界单位；`(x,y)` 映射为 `(x-w/2, visual_height, y-h/2)`。表现层可对视角做 180° 翻转，输入使用逆变换。
4. 拾取使用相机射线与地平面的数学交点，再转换为 tile；合法性继续由原逻辑规则判定，正式出牌继续走既有服务端入口。
5. 飞行高度、跳跃、投射弧线、阴影和震屏是纯表现量，不能进入 sim、配置经济权威或胜负判定。
6. PvE/PvP 最终共用 presenter；网络层负责权威输入和重连，presenter 读取状态，不另建战斗状态真相源。
7. 模型交付使用 GLB；Blender 可编辑源文件由 `.gdignore` 隔离。角色采用真正几何体与骨骼动画，施工代理逐项验收替换。

## 后果与验收

- 不需要仅因画面迁移改变 Go 经济、WS 协议或服务端数据库。
- 旧的 2D 投影/绘制规格被新的 3D 表现目标取代；卡牌数值、地形、部署和联网规则继续有效。
- 需重新验证屏幕落点、正反视角、遮挡、教程指引和移动端性能；3D 同画面节点/骨骼成本不能沿用精灵时代假设。
- 本轮独立场地预览不发战斗/经济指令，不构成可写离线模式；不改变正式在线门禁。
- D0 及后续成功标准见 [迁移施工图](../../PLAN_V5_3D.md)，进度见 HISTORY.md / Jira。
